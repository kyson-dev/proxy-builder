# 文档规则

日常修改只需阅读 [CLAUDE.md](../CLAUDE.md)。当一条信息不知道应放在哪里时，再回到本文件。

## 结构

```text
README.md                       项目入口和导航
CLAUDE.md                       修改仓库时的短规则
docs/
├── README.md                   本文件
├── architecture/overview.md   当前系统组成和职责
├── adr/                        决策索引、模板和历史决策
└── design/                     具体接口、schema、路径和规则
```

当前不创建 `runbooks/`。只有新命令已经实现，且能写出可独立验证的操作步骤时才增加 Runbook。

## 信息归属

依次判断，命中后停止：

```text
1. 解释为什么作出边界级决策，改变时需重新评估系统？  -> adr/
2. 描述当前组成、职责或状态所有权？                  -> architecture/overview.md
3. 定义具体接口、字段、格式、路径或算法？              -> design/
4. 人在特定情形下执行的步骤？                         -> runbooks/（存在后）
5. 都不是？                                           -> 不进入 docs/
```

研究笔记、未决定的选项、实施清单，以及可从代码、配置、日志或运行系统直接得到的信息，不在 `docs/` 保存副本。

## 边界与篇幅

| 类别 | 边界测试 | 上限 |
| --- | --- | --- |
| 根 README | 其他文档已有细节时只保留链接 | 约 60 行 |
| Architecture | 不改变组件职责的重构会令它失效，则它属于实现细节 | 约 250–300 行 |
| ADR | 改变该决定无需通知或更新其他文档，则不值得写 ADR | 每份约 120 行 |
| Design | 没有具体名称、格式或规则则属于 Architecture；人工步骤属于 Runbook | 每份约 200 行 |
| Runbook | 凌晨三点仅凭该文档能否安全执行并判断成功 | 核心步骤一屏 |

Design 是字段、格式、命令和路径的唯一所有者，其他文档只链接，不复制。

## 当前状态与目标设计

- [Architecture](architecture/overview.md) 只描述仓库当前已实现、可观察的系统。
- [ADR](adr/README.md) 保存已接受决策及其原因。
- [Design](design/README.md) 是当前重构必须实现的目标契约；实现前必须明确标记为尚未落地。
- 实现完成并验证后，更新 Architecture 反映新现状，并移除 Design 中的“尚未实现”标记。

## 新增、修改和删除

- 新建文档前，先确认现有文档没有拥有该信息，并说明不新增会造成什么具体问题。
- 新增基线以外的类别前，必须说明未满足的需求、现有类别为何不能承载、边界以及维护来源，并获得明确批准。
- Architecture 边界变化时检查是否需要 ADR，以及相关 Design 是否仍成立。
- Design 接口变化时检查代码、测试和 Runbook；名称变化时同时检查配置、日志和工作流。
- 优先原地编辑。禁止使用 `-v2`、`-final`、`-new`、`-old`、`-copy` 或日期后缀保存文档历史。
- 删除重复和失效文档。Accepted ADR 不删除、不重写；用新 ADR 取代并双向链接。

## 防膨胀规则

1. 一个事实只有一个权威位置。
2. 超过篇幅上限时拆分或下沉细节。
3. 文档描述现状或已接受的精确契约，不保存模糊计划。
4. 不维护“摘要中的摘要”；链接权威文档。
5. 删除一句话不会损失事实、决策或指令时，删除它。
